## 팀 회의 결과 — 초안에서 고친 것 (2026-08-15)

네 트랙 담당이 각자 자기 영역을 상세화하면서 초안의 전제 셋을 반박했고, 전부 수용했다.
상세는 `docs/tracks/` 아래 네 문서.

| 초안 | 고친 것 | 근거 |
| --- | --- | --- |
| W0(액자 걷어내기)을 최우선 | **액자 제거는 W3에 흡수. 최우선은 "타이포 스케일 토큰 확정"(반나절)** | `.phone`에 `transform:scale`이 없고 `@media(max-width:520px)`가 이미 액자를 걷는다. 즉 **실기기 375px에서 지금 이 순간 5.5px 라벨이 렌더된다.** 타이포는 액자의 후속 작업이 아니라 독립된 결함이다. 그리고 액자는 컨테이너 하나라 W3의 새 `layout.tsx`가 자연히 대체한다 — 따로 걷으면 두 번 만든다 |
| W6(AI) 선행 = W2 | **W6a(출력 계약)를 W2 앞으로** | 계약이 먼저 "수령인 여러 명"을 정의하지 않으면 W2가 자기 표현을 발명하고 나중에 둘을 맞춘다 |
| W5(결제)는 요금 결정 대기 | **W4는 요금과 무관하게 진행** | `delivery_pricing` 테이블을 두면 $9→$15가 insert 한 줄. 확정된 이송의 `fee_cents`는 이미 동결이라 소급되지 않는다 |
| W6에 카탈로그 포함 | **카탈로그를 W8(매장 방문)로 이동** | 책상일이 아니라 현장일이다. 매장 방문 체크리스트를 카탈로그 스키마와 1:1로 맞춘다 |
| W6에 지도·도보시간 포함 | **W6에서 제외** | AI 문제가 아니라 지도 벤더·약관 결정이다 |
| W7을 통째로 마지막 | **4조각으로 분해** | manifest·설치·오프라인 셸은 지금 가능, SW 캐시는 W3 후, 아웃박스는 W1 후, **오프라인 QR 패스는 W4 후**(캐시할 토큰이 W4에서 생긴다) |
| 다크 테마를 뷰포트 전환과 함께 | **토큰화 후로** | 하드코딩 hex 141종을 두 벌 만들게 된다 |

## 디자인 감사 — 실측 (추정 아님)

Ubuntu 폰트의 `hmtx` 테이블을 직접 파싱해 실제 글자 폭으로, 대비는 조상 사슬로 배경을 해석해 WCAG 상대휘도로 계산한 값.

| 항목 | 결과 |
| --- | --- |
| font-size 선언 233개 | **10px 미만 180개(77%)** · 12px 미만 196개(84%) |
| 인터랙티브 규칙 42개 | **44px 미달 35개(83%)** · 최악 ≈7px (과거 여행 펼치기 버튼) |
| 색 선언 197개 | **대비 미달 60개(30%)** · 그중 **46개가 `--muted` 토큰 하나** |
| 하드코딩 hex | **141종 / 161회** (색 사용의 44%가 토큰 밖) |
| 4px 그리드 준수 | 337개 중 81개(24%) |
| 유니코드 아이콘 | 18종 / 75회 |

역할 기준 최악 셋: 배송 단계 라벨 5px(대비 2.21) · 취급 구분(냉장/파손) 5px에 스크린리더가 "눈송이/마름모"로 낭독 · 예산 초과 승인 버튼 6px에 터치 타깃 13px.

**초안에 없던 차단 항목:** 포커스링 `#347d8d`가 네이비 위에서 2.82:1이라 **추적 화면에서 키보드 포커스가 사실상 안 보인다**(아웃라인을 "지우지 않는 것"만으로 부족하다) · `themeColor: #12333c`가 어느 토큰도 아닌 유령 값(`--navy`는 `#12343d`) · `layout.tsx`의 외부 Figma CDN 스크립트가 프로덕션에 남아 있다.

## 작업 분할 — 수정본

### T0. 스케일 토큰 확정 ★ 최우선 (반나절)
타이포 스케일·간격·표면별 색 토큰을 먼저 박는다. **밝은 표면용과 네이비 표면용 토큰이 따로 필요하다** — 다크 화면이 6개고, 한 벌로는 한쪽이 반드시 실패한다. 포커스링도 표면별로.
**담당** design-lead · **선행** 없음 · **왜 최우선** 이걸 안 정하면 W2·W3·W4가 각자 다른 크기로 화면을 만들고 전부 다시 만진다

### T1. 데이터 정합 (T0과 병렬)
인덱스 키 4종 제거 → `stops` UUID. `GET /api/state` 한 번으로 하이드레이션. localStorage는 사용자별 네임스페이스 캐시로 강등.
- `replacementIds`는 **소멸한다** — 교체는 상태가 아니라 사건이라 `replaced_stop_id`가 붙은 새 행이다
- **임포트 금지 3종**: `deliveryStep`·`transferStatus`(사용자가 버튼으로 올린 값이라 원장이 첫 행부터 거짓이 된다) · `memoryEnabled`(로컬 기본값이 opt-out이라 옮기면 동의를 위조한다)
- 산출물을 `lib/state/`로 한정하고 `page.tsx`는 어댑터만 — W3가 그 파일을 해체하므로 경계를 그어야 충돌하지 않는다
**담당** platform · **크기** L

### T2. AI 출력 계약 (T1과 병렬)
다중 수령인·여행별 통화·예비비를 표현하는 새 스키마. 모델은 **버킷 금액을 절대 내지 않고** 총액과 범위만 낸다(예비비를 발설할 방법을 구조적으로 제거). 금액은 주 단위 정수.
**담당** ai-planner · **크기** M

### T3. 4탭 IA + 셸 (T0 후)
라우트 기반(`/trips`, `/trail`, `/ask`, `/bags`) + `(app)` 라우트 그룹. **첫 커밋이 액자 제거**다. `useSyncExternalStore` 스토어 하나, 라이브러리 추가 없음. 한 줄 압축 스타일 유지.
- T3-A(셸·4탭·라우트 골격)는 선행 없음, T3-B(shop/bags 이관)는 T1 선행
**담당** app · **크기** L

### T4. 다중 수령인 + 3버킷 지갑 (T1·T2 후)
`recipients` CRUD · `plan_allocations` · 등가 제약 · 예산 초과 재배분 승인 화면.
⚠️ **배정액에 10 단위 스냅을 적용하면 안 된다** — 58/68/39/45가 60/70/40/50이 되어 총액이 11 어긋난다. 총액만 스냅.
**담당** product → app + platform · **크기** L

### T5. 이송 실물화 (T1 후 · 요금과 무관)
파트너 지점 · QR(`TRLP1.payload.HMAC`, payload에 PII 없음, 검증은 서명→만료→해시 상수시간 순) · 봉인 태그 · 커스터디 서버 소유 · 실패 분기 3종 · 영수증 실체화.
`Preview next status`는 `TRAIL_SIMULATOR=on` + `simulated` 행 한정 + 404로 분리.
**담당** platform + product · **크기** L

### T6. 결제 정합 (T4 후 · 요금 결정 필요)
`delivery_pricing` 도입 → 요금 변경이 insert 한 줄. 예비비와 청구액 정합, 배송비 > 예비비일 때 flexible 인출 승인, 취소 시 환원 규칙.
**담당** platform · **크기** M

### T7. 웹앱 (조각별 선행이 다름)
manifest·설치·`/offline`(지금 가능) → SW 캐시(T3 후) → 아웃박스(T1 후) → **오프라인 QR 패스(T5 후)**.
SW 캐시 금지 목록(인증 세션 오염 방지)을 먼저 정한다.
**담당** app · **크기** M

### T8. 사업 검증 + 카탈로그 (지금 병렬 · 코드 아님)
$0 실험 4개(매장 8곳 · 호텔 프런트 8곳 · 위탁 네트워크 접촉 · 가격 인터셉트). **매장 방문 시 카탈로그 데이터를 함께 수집**한다 — 방문 체크리스트를 `stores`/`products` 스키마와 1:1로.
**담당** 사용자 + venture-strategist

## 순서

```
지금 ── T0 토큰(반나절) ──→ T3 셸·4탭 ──→ T7 SW캐시
    ├── T1 데이터 정합  ──┬→ T4 수령인·지갑 → T6 결제(요금 결정 후)
    ├── T2 AI 계약     ──┘
    ├── T5 이송 실물화(T1 후) ──→ T7 오프라인 QR
    └── T8 사업 검증 + 카탈로그 (오프라인, 지금 시작)
```

## 데모데이 최소 경로
로그인 → 여행 등록 → AI 대화 → **다중 수령인 계획** → 경로 → 구매 기록 → **예산 초과 승인** → 가방 선택 → 결제 → 드롭오프 QR → 추적 → 영수증. 실패 분기는 **이송 불가 하나만** 시연해도 "실패를 설계했다"가 성립한다.

## 결정 — 확정됨 (2026-08-15)

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 배송 요금 | **$15**, `delivery_pricing` 테이블로(Toronto 기준 3봉투 $15 + 추가 $4) | $9는 완벽 배칭에서도 건당 33센트다. 요금을 코드 상수가 아니라 시효 있는 데이터로 두면 실험 결과로 바꿔도 확정된 이송은 소급되지 않는다 |
| 다일 여행 2회 배송 | **허용.** 유일성을 `draft`/`awaiting_payment`로 좁힘 | 4박 여행에서 2일차·3일차 각각 발송은 정상 사용이다 |
| 플랜 외 가방 지출 | **기록 가능.** `purchases.stop_id`를 nullable로, `unplanned_label` 추가 | 가방은 보낼 수 있는데 그 돈을 못 적으면 지갑 `spent`가 거짓이 되고 예산 초과 화면이 안 뜬다 |
| 재고 문의(`Request`) | **기능 보류.** 스키마는 두되 UI·프롬프트에서 노출 금지 | `store_inquiries`에 수신자가 없다. 연락 경로 없이 "물어봐 드릴까요"는 우리가 만든 거짓말이다. T8 매장 방문에서 연락처를 확보한 뒤 연다 |
| 탭 구성 | `Trips · Trail · Ask AI · Bags` | APP_SPEC §1.1 그대로 |
| 데모 화면 | **모바일 우선 + 데스크톱은 최대폭 가운데 정렬** | 노트북 시연에서도 깨져 보이지 않으면서 폰이 기준으로 남는다 |
| 다크 테마 | **토큰화 이후로** | 하드코딩 141종을 두 벌 만들게 된다 |
| Figma CDN 스크립트 | **프로덕션에서 제거** | 외부 스크립트를 상시 로드할 이유가 없다 |
