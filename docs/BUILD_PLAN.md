## 작업 분할 — 8개 트랙

### W0. 액자 걷어내기 (모든 것의 선행)
390px 폰 목업(`.stage > .phone`)을 실제 뷰포트로 전환하고, 그와 **한 묶음으로** 타이포를 재조정한다. 현재 5.5px 탭 라벨·6px 캡션은 액자 안이라 성립하던 값이라 액자를 걷으면 읽히지 않는다.
- 실제 뷰포트 · `100dvh` · safe-area · 태블릿/데스크톱 최대폭
- 본문 최소 12px, 라벨 최소 10px, 터치 타깃 44px, 대비 4.5:1 실측
- 아이콘을 유니코드 문자(`⌂ ✦ ⌁ ▣ ◎`)에서 SVG로
- 폰 목업은 `/workflow` 쇼케이스에만 남긴다
- **담당** design-lead + app-engineer · **크기** M · **선행** 없음
- **왜 먼저** 새 화면을 옛 액자 안에 만들면 전부 다시 만든다

### W1. 데이터 정합 (W0과 병렬)
배열 인덱스(0/1/2) 식별을 `stops` UUID로 바꾸고, 화면 상태를 서버로 옮긴다.
- `purchases`·`selectedBags`·`replacementIds`·`savedStops` 4종의 인덱스 키 제거
- `GET /api/state` 한 번으로 하이드레이션, localStorage는 캐시로 강등
- 스키마 추가 12개 · 오프라인 멱등키(`stops`/`store_inquiries`/`budget_changes`) · `trips.status='active'` 유일성 제약
- **담당** platform-engineer · **크기** L · **선행** 없음
- **왜 먼저** 수령인을 추가·삭제하는 순간 인덱스 키가 어긋나 **구매 기록이 다른 항목에 붙는다**. 이건 UI 버그가 아니라 지출 기록 손실이다

### W2. 다중 수령인 + 3버킷 지갑
- `recipients` CRUD(‘Myself’ 포함) · `plan_allocations` · 등가 제약
- 지갑 계산 확정: **쇼핑 가능액 = planned − spent**, flexible은 승인 필요
- 예산 초과 재배분 승인 화면(`budget_changes`) — 헌법 1번이 실제로 걸리는 유일한 화면
- **담당** product-lead(명세) → app + platform · **크기** L · **선행** W1

### W3. 4탭 IA 전환
`Trips · Trail · Ask AI · Bags` + 계획 화면 안의 `Gifts|Map|Budget|Delivery`. 기존 9화면 재배치, `profile` 해체.
- **담당** app-engineer · **크기** L · **선행** W0
- 지도 탭은 여기서 자리만 잡고 실제 지도는 W6

### W4. 이송·커스터디 실물화
- 파트너 드롭오프 지점 · QR(서명 토큰, DB엔 해시) · 가방별 봉인 태그
- 커스터디 이벤트를 서버 소유로. **`Preview next status` 버튼 폐기**, 시뮬레이션은 개발용 API로 분리
- 실패 분기 3종: 이송 불가 / 호텔 인계 실패 / 지연·봉인 이상 신고
- 영수증 실체화(태그 ID 집합 대조)
- **담당** platform + product-lead · **크기** L · **선행** W1

### W5. 결제 정합 ⚠️ 요금 결정 대기
- **요금을 $9 → $15로 올릴지 결정이 선행**(사업 검증 권고). 코드 `DELIVERY_RESERVE`, 결제 화면, 지갑 예시, 피그마 카피가 한 번에 바뀐다
- 예비비와 실제 청구액 정합 · 배송비 > 예비비일 때 flexible 인출 승인
- 이송 취소 시 예비비 환원 규칙(현재 미정)
- **담당** platform-engineer · **크기** M · **선행** W2 + 요금 결정

### W6. AI 정합 + 환각 차단
- 출력 스키마를 다중 수령인·통화·예비비로 확장(현재는 수령인 문자열 1개, CAD 고정)
- `stores`·`products` 시딩 → **매장명 금지를 "주어진 후보에서만 고르기"로 전환**
- 지도·도보시간 실데이터
- **담당** ai-planner · **크기** M · **선행** W2(스키마), 카탈로그는 즉시 시작 가능

### W7. 웹앱(PWA)
manifest · 서비스워커 · 오프라인 셸 · **오프라인에서도 뜨는 QR 패스** · 동기화 대기 칩
- **담당** app-engineer · **크기** M · **선행** W0 + W3

### W8. 사업 검증 (코드 아님 · 지금 병렬)
$0 실험 4개: 매장 8곳 · 호텔 프런트 8곳 · 위탁 네트워크 접촉 · 가격 인터셉트. 결과가 W5의 요금과 W4의 파트너 모델을 확정한다.
- **담당** 사용자 + venture-strategist · **선행** 없음

## 순서

```
지금 ── W0 액자          ─┐
    ├─ W1 데이터 정합     ─┼→ W2 수령인·지갑 → W5 결제
    ├─ W6 카탈로그 시딩   ─┘   W3 4탭 IA
    └─ W8 사업 검증(오프라인)   W4 이송 실물화 → W7 PWA
```

병렬 가능: **W0 · W1 · W6(카탈로그) · W8**은 서로 안 막는다. 첫 주에 넷을 동시에 연다.
직렬 강제: W1 → W2 → W5, W0 → W3 → W7.

## 데모데이용 최소 경로
46화면을 다 만들 시간은 없다. 시연에 필요한 건: 로그인 → 여행 등록 → AI 대화 → **다중 수령인 계획** → 경로 → 구매 기록 → **예산 초과 승인** → 가방 선택 → 결제 → 드롭오프 QR → 추적 → 영수증. 실패 분기는 **이송 불가 하나만** 시연해도 "우리는 실패를 설계했다"가 성립한다.
