# TRAIL 와이어프레임 UX 설문 (v1)

> **웹 버전: `/survey/ux`** — 배포·자극물·응답 내려받기는 [WEB.md](WEB.md). 문항을 고칠 때는 이 파일과 `lib/survey/`를 같이 고친다.

대상: **토론토 등 해외 도시에 1박 이상 숙박하며 현지에서 쇼핑하는 여행자**
자극물: 최종 와이어프레임 12프레임 (클릭 가능한 프로토타입 또는 순차 이미지)
방식: 과업 기반 비대면(unmoderated) 원격 테스트 + 사후 설문. 모더레이티드로 돌릴 경우 §3의 과업만 발췌해 씽크얼라우드로 쓴다.
예상 소요: **18–22분** (본조사) · 축약판은 맨 아래 참조 (9분)
표본 목표: n=60 (과업당 완료율 ±12%p 신뢰구간). 최소 n=30.

> **운영 원칙**
> 1. 응답자에게 "이건 아직 못 만든 기능"이라고 알려주지 않는다. 화면에 `Sample`/`Simulated`가 붙어 있는지 **응답자가 알아채는지**가 측정 대상이다.
> 2. 과업 지시문에 화면 속 단어(Wallet, Arrange delivery, Drop-off)를 쓰지 않는다. 라벨을 그대로 주면 탐색 성공을 측정할 수 없다.
> 3. 지불의사는 **반드시 과업을 다 끝낸 뒤**에 묻는다. 앞에 두면 가격이 전체 평가를 오염시킨다.

## §0. 동의 · 스크리너

**A0.** 본 조사는 출시 전 서비스 화면에 대한 사용성 조사입니다. 응답은 익명 처리되며 언제든 중단할 수 있습니다. 참여에 동의하십니까? `동의 / 동의하지 않음(→ 종료)`

**S1.** 최근 **3년 이내** 해외로 1박 이상 여행한 적이 있습니까? `있다 / 없다(→ 종료)`

**S2.** 그 여행 중 **현지 매장에서 물건을 구매**한 적이 있습니까? (면세점 제외) `있다 / 없다(→ 종료)`

**S3.** 다음 중 경험한 것을 모두 고르세요. *(복수응답 — 스크리너 겸 문제 인식 측정)*
- ① 산 물건을 들고 다니느라 남은 일정이 불편했다
- ② 무겁거나 깨질 것 같아서 사려던 걸 **포기했다**
- ③ 짐을 맡기려고 숙소로 돌아갔다 다시 나왔다
- ④ 유료 짐보관 서비스(Bounce, Stasher 등)를 써 봤다
- ⑤ 위 어느 것도 해당 없음

> **쿼터**: ②를 고른 응답자를 최소 40%로 채운다. 이 서비스의 매출 논리(매장이 잃는 매출)가 그들에게만 성립한다.

**S4.** 여행 중 하루 쇼핑 예산은 보통 어느 정도입니까? `~5만원 / 5–15만원 / 15–30만원 / 30–50만원 / 50만원 이상`

**S5.** 여행 계획에 AI 챗봇(ChatGPT 등)을 써 본 적이 있습니까? `자주 / 가끔 / 한두 번 / 없음`

**D1–D3.** 연령대 / 성별 / 동반 형태(혼자·커플·친구·가족·단체)

## §3. 과업 (T1–T6)

각 과업 직후 공통 3문항을 반복한다.

> **[과업 공통 문항]**
> **Q-a.** 과업을 끝냈습니까? `끝냈다 / 끝냈다고 생각하지만 확신 없다 / 못 찾았다`
> **Q-b.** 이 과업은 얼마나 쉬웠습니까? *(SEQ, 매우 어려웠다 1 — 매우 쉬웠다 7)*
> **Q-c.** 헷갈리거나 예상과 달랐던 부분이 있었다면 적어 주세요. *(서술)*

### T1 — 여행과 예산 등록 (F2·F3)

> 지시문: "다음 주 토론토에 3일간 갑니다. 이 앱에 그 여행을 등록하고, 쇼핑에 쓸 돈의 상한을 정해 보세요."

**T1-1.** 앱이 대화로 질문을 던지는 방식은, 폼(입력칸)에 직접 적는 방식과 비교해 어땠습니까?
`대화가 훨씬 낫다 / 대화가 조금 낫다 / 비슷하다 / 폼이 조금 낫다 / 폼이 훨씬 낫다`
**T1-2.** 질문 개수는 어땠습니까? `너무 적다 / 적당하다 / 너무 많다`
**T1-3.** 대답하기 **불편하거나 답하기 싫었던 질문**이 있었습니까? *(복수 — 도시 / 날짜 / 누구를 위해 / 예산 / 숙소 / 취향 / 없음)*

> **분석**: T1-3에서 **숙소(호텔)** 를 고른 비율을 본다. 프라이버시 저항이 여기서 나오면 온보딩 순서를 바꿔야 한다.

### T2 — 계획 확인과 수정 (F5·F6)

> 지시문: "앱이 만들어 준 계획을 확인하고, 그중 한 사람에게 줄 선물을 다른 것으로 바꿔 보세요."

**T2-1.** 계획 요약 카드(F5)의 내용은 내가 말한 것을 정확히 반영했습니까? *(전혀 1 — 매우 7)*
**T2-2.** 추천된 상품이 **실제로 그 매장에 있을 것 같다**고 느꼈습니까? *(전혀 1 — 매우 7)*
**T2-3.** T2-2에서 4점 이하를 고른 이유는? *(분기 서술)*
**T2-4.** 계획을 바꾸고 싶을 때 어느 쪽을 쓰겠습니까? `직접 수정(Edit) / AI에게 말하기 / 상황에 따라 다름`

### T3 — 동선 확인 (F7)

> 지시문: "오늘 몇 군데를 들러야 하는지, 그리고 그 순서를 확인해 보세요."

**T3-1.** 지도와 아래 목록 중 어느 쪽에서 정보를 얻었습니까? `지도 / 목록 / 둘 다 / 둘 다 못 읽음`
**T3-2.** 이 동선을 실제로 따라다닐 의향이 있습니까? *(전혀 1 — 매우 7)*
**T3-3.** 동선을 보고 **더 알고 싶었지만 화면에 없던 정보**는? *(서술)*

### T4 — 예산 상태 이해 (F8) 🔑

> 지시문: "지금 이 여행에서 **앞으로 쇼핑에 더 쓸 수 있는 금액**이 얼마인지 말해 주세요."

**T4-1.** 얼마입니까? *(숫자 입력)*

> **정답**: `Planned $210 − Spent $176 = CAD $34`. **Flexible $31은 승인 없이 쓸 수 없으므로 포함하면 오답이다.**
> **분석**: 정답률이 곧 지갑 화면의 성패다. `$65`(= 34+31)로 답한 비율을 별도 집계한다 — flexible이 잠겨 있다는 게 안 읽힌다는 뜻.

**T4-2.** `Flexible CAD $31`은 어떤 돈이라고 이해했습니까? *(서술)*
**T4-3.** `Reserved for delivery CAD $9`는 어떤 돈이라고 이해했습니까? *(서술)*
**T4-4.** 5개 항목(Total / Planned / Spent / Reserved / Flexible) 중 **없어도 될 것 같은 항목**이 있습니까? *(복수 + 없음)*

### T5 — 짐 배송 요청 (F9·F10·F11)

> 지시문: "쇼핑백 3개가 생겼습니다. 이걸 직접 들고 다니지 않고 숙소로 보내 보세요."

**T5-1.** `Blue Banana Market`은 무엇이라고 이해했습니까?
`짐을 맡기는 곳 / 선물을 사는 매장 / 배송 회사 / 잘 모르겠다`
**T5-2.** 배송비 CAD $9는 **언제** 청구된다고 이해했습니까? `지금 / 짐을 맡길 때 / 호텔에 도착한 뒤 / 모르겠다`
**T5-3.** QR 화면(F11)의 안내만 보고 매장에서 무엇을 해야 할지 알겠습니까? *(전혀 1 — 매우 7)*
**T5-4.** 이 단계에서 **불안하게 느껴진 것**을 모두 고르세요. *(복수)*
- ① 짐이 분실될까 봐 ② 매장 직원이 이 서비스를 모를까 봐 ③ 호텔이 받아주지 않을까 봐
- ④ 결제가 잘못될까 봐 ⑤ 시간 안에 도착하지 않을까 봐 ⑥ 특별히 불안하지 않았다

### T6 — 배송 추적 (F12)

> 지시문: "맡긴 짐이 지금 어디쯤 있는지 확인해 보세요."

**T6-1.** 짐이 지금 어디에 있습니까? `매장 / Trail이 수거해 이동 중 / 호텔 도착 / 모르겠다`
**T6-2.** 이 화면을 보고 **얼마나 안심**이 됩니까? *(전혀 1 — 매우 7)*
**T6-3.** 여기에 추가로 있어야 할 정보는? *(복수 — 기사 이름·연락처 / 실시간 위치 지도 / 사진 인증 / 호텔 담당자 이름 / 없음 / 기타)*

## §4. 개념 이해도 (전 과업 종료 후) 🔑

이 서비스의 제품 규칙이 화면만 보고 전달되는지 직접 측정한다. **정오답 문항**이며 응답자에게는 정답 여부를 알리지 않는다.

**E1.** 앱에서 상품에 `Request`를 누르면 어떻게 됩니까?
`① 주문된다 ② 예약된다 ③ 매장에 재고가 있는지 문의된다 ④ 모르겠다` → **정답 ③**

**E2.** 물건은 누가 결제합니까?
`① 앱이 대신 결제 ② 내가 매장에서 직접 ③ 호텔이 대납 ④ 모르겠다` → **정답 ②**

**E3.** 실제 가격이 계획보다 비싸서 예산을 넘겼습니다. 앱은 어떻게 합니까?
`① 알아서 다른 항목 예산을 줄인다 ② 새 배분을 제안하고 내 승인을 기다린다 ③ 항목을 자동으로 지운다 ④ 모르겠다` → **정답 ②**

**E4.** 화면에서 `Sample` 또는 `Simulated`라고 표시된 것을 본 적이 있습니까? 있다면 어떤 화면이었습니까? *(예/아니오 + 서술)*

> **분석**: **인지율**을 본다. 50% 미만이면 표기가 사실상 존재하지 않는 것이고, 이는 제품 규칙 3의 위반이다. 인지한 응답자의 신뢰(§5) 점수가 유의하게 낮지 않은지도 함께 본다 — 낮다면 정직한 표기가 전환을 깎는다는 뜻이고, 그걸 감수할지는 팀이 결정할 문제다.

**E5.** 이 앱이 **내 승인 없이 스스로 해도 괜찮다**고 생각하는 것을 모두 고르세요. *(복수)*
`상품 추천 / 동선 재계산 / 예산 재배분 / 항목 삭제 / 대체 상품으로 교체 / 배송 신청 / 결제 / 아무것도 없음`

> **분석**: '추천·동선'만 고른 응답자 비율이 곧 현재 승인 게이트 설계의 지지율이다. 예산 재배분까지 위임하겠다는 비율이 높으면 게이트를 옵션으로 풀 여지가 있다.

## §5. 전체 평가 척도

**U1–U2 (UMUX-Lite).** *(전혀 아니다 1 — 매우 그렇다 7)*

- U2: 이 앱은 쓰기 쉽다

**SUS.** 표준 10문항(1–5) 전체. *축약판에서는 생략하고 UMUX-Lite만 쓴다.*

**TR1–TR5 (신뢰).** *(1—7)*

| | 문항 |
| --- | --- |
| TR1 | 이 앱이 추천한 상품이 실제로 매장에 있을 것이다 |
| TR2 | 이 앱에 짐을 맡겨도 잃어버리지 않을 것이다 |
| TR3 | 이 앱은 내 돈을 내 허락 없이 쓰지 않을 것이다 |
| TR4 | 이 앱이 보여주는 도착 예정 시각은 믿을 만하다 |
| TR5 | 이 앱은 못 하는 것을 할 수 있다고 말하지 않는다 |

- AI1: AI가 내 선물 취향을 이해했다고 느꼈다
- AI2: AI가 물어본 질문들은 필요한 질문이었다
- AI3: AI가 지어낸 것 같은 정보가 있었다 *(역문항 — 채점 시 역코딩)*

## §6. 실패 분기 시나리오

제품 규칙 4의 네 가지 실패 경로에 대한 기대 반응을 직접 묻는다. 각 시나리오를 문장으로 제시하고 답을 받는다.

**F-1.** *"조건에 맞는 상품을 못 찾았습니다."* — 앱이 어떻게 해 주길 바랍니까? *(서술)*
**F-2.** *"매장에서 실제 가격이 계획보다 CAD $40 비쌌습니다."* — 어떻게 해 주길 바랍니까? *(서술)*
**F-3.** *"오늘 이 짐은 배송할 수 없습니다."* — 그 사실을 **언제** 알아야 합니까?
`짐을 맡기기 전 / 맡긴 직후 / 배송 예정 시각 전 / 상관없다`
**F-4.** *"호텔 프런트가 짐 수령을 거부했습니다."* — 다음으로 무엇을 기대합니까? *(서술)*

**F-5.** 위 네 상황 중 **실제로 겪는다면 이 서비스를 다시 안 쓸 것 같은 것**은? *(단일 선택 + 없음)*

## §7. 지불의사 (van Westendorp)

> 제시문: "쇼핑백 3개(약 2.4kg)를 매장에서 숙소까지 그날 저녁에 배송해 줍니다."
> **주의: CAD $9라는 숫자를 이 섹션 앞에 다시 노출하지 않는다.** 앵커링이 걸리면 PSM 곡선이 무의미해진다.

**P1.** 너무 비싸서 쓰지 않을 가격은? *(원 단위 입력)*
**P2.** 비싸다고 느끼지만 고민해 볼 가격은?
**P3.** 싸다고 느껴 이득이라 생각할 가격은?
**P4.** 너무 싸서 품질이 의심스러운 가격은?

**P5.** 위 서비스가 **CAD $9(약 9,000원)** 라면 쓰시겠습니까? *(전혀 1 — 매우 7)*
**P6.** 이 비용은 누가 내는 게 자연스럽다고 생각합니까?
`내가 전액 / 내가 일부, 매장이 일부 / 매장이 전액 / 호텔이 전액 / 잘 모르겠다`
